    Supported versions¶

    What Momo v0.10.0 is built and tested against. "Tested" means a job in .github/workflows/ci.yml runs it. Anything not listed there is untested, not necessarily broken.

    Module¶

    Item Value
    Module path github.com/azrtydxb/momo
    Version v0.10.0 (tags use a v prefix)
    Install go get github.com/azrtydxb/momo@v0.10.0
    CLI go run github.com/azrtydxb/momo/cmd/momo (or go install the same path)

    Databases¶

    A database is usable when a driver package for it exists under driver/:

    • PostgreSQL: usable through driver/pgxdriver (vector builders: yes). Migrations: migrate/postgres, run by momo migrate.
    • SQLite: usable through driver/sqlitedriver (needs cgo, not on Windows, vector builders: yes) and driver/sqlitepure (vector builders: no). Migrations: migrate/sqlite, library only (momo migrate does not select it).
    • MySQL and MariaDB: usable through driver/mysqldriver (vector storage and builders depend on the server version). Migrations: migrate/mysql, library only (momo migrate does not select it).

    Servers the integration jobs run against: PostgreSQL 16 and 17 with pgvector (see below), and MySQL 8.4, MySQL 9.7 and MariaDB 11.8 for the MySQL driver. Vector support on the MySQL family depends on the server version: MySQL 8.4 has no VECTOR type, MySQL 9.x stores vectors but has no distance function, and MariaDB 11.8 has L2 and cosine distance functions (see MySQL and MariaDB).

    Go¶

    Item Value
    Minimum (go.mod go line) 1.26.10
    CI matrix 1.26 and 1.27 for unit, compile-fail, race, fuzz smoke and integration jobs
    Single-version CI jobs lint and bench-module (1.26); bench smoke, govulncheck, Windows and macOS (1.27)
    Older than 1.26.10 not supported
    cgo driver/sqlitedriver (mattn go-sqlite3 and sqlite-vec) needs cgo and a C toolchain and does not build on Windows; a build without cgo gets a stub whose Open returns ErrUnsupported; driver/sqlitepure needs no cgo and is tested with CGO_ENABLED=0 (make test-sqlitepure). The macOS job sets CGO_ENABLED=1; the Linux jobs use the default, which is on

    Operating systems¶

    OS CI job What runs
    Linux ubuntu-latest every job, including PostgreSQL integration tests
    macOS macos-latest CGO_ENABLED=1 go test ./... (unit tests, no database)
    Windows windows-latest go test ./... and go test -tags integration ./driver/sqlitepure/... ./internal/sqlshared/... (pure-Go SQLite, no server)

    Integration tests (real PostgreSQL, pgvector, PgBouncer) run on Linux only.

    The integration-mysql job runs the integration suite against MySQL 8.4.13, MySQL 9.7.4 and MariaDB 11.8.9 (one service container per matrix entry, on Go 1.26 and 1.27). The bench-module job vets, tests and tidy-checks the separate bench module against PostgreSQL 17 with pgvector, runs its integration tests, the hook-overhead benchmark (make bench-hooks), the benchmark suite smoke run and the allocation gate (make bench-gate).

    PostgreSQL¶

    Item Value
    Tested major versions 16 and 17 (images pgvector/pgvector:0.8.7-pg16 and 0.8.7-pg17)
    Other majors untested; no minimum is enforced in code and none is documented
    MERGE the momo.Merge builder; it reads server_version_num (ServerVersioner) and returns ErrUnsupported below PostgreSQL 15, and for .Returning below PostgreSQL 17
    Authentication in tests password (postgres and momo_app roles); TLS is off in CI (sslmode=disable)
    Driver pgx v5 pool through pgxdriver.NewPool or pgxdriver.New; database/sql through pgxdriver.FromSQLDB

    pgvector¶

    Item Value
    Tested version 0.8.7 (pinned; TestPgvectorVersionPinned fails on any other version in CI)
    Iterative scan, hnsw.max_scan_tuples, hnsw.scan_mem_multiplier, ivfflat.max_probes 0.8.0 or newer; enforced: vecsearch.Apply returns ErrUnsupported on an older or missing extension
    vector, halfvec, sparsevec, bit types and the l1, hamming, jaccard operators no version check in Momo. Upstream pgvector added halfvec, sparsevec, l1 and jaccard in 0.7.0; that is not asserted by this repository, so treat 0.7.0 as an unverified lower bound and use 0.8.x
    Installation server-side package or image; Momo never runs CREATE EXTENSION at connect time; a migration creates it and a missing extension surfaces as ErrUnsupported

    PgBouncer¶

    Item Value
    Tested version 1.26.1 (image edoburu/pgbouncer:v1.26.1-p0)
    Pool mode transaction
    Client authentication scram-sha-256 (AUTH_TYPE)
    Prepared statements CI sets MAX_PREPARED_STATEMENTS=0; Momo's default exec mode creates no named prepared statements (checked on the wire by TestPgBouncerNoNamedPreparedStatements)
    Exec modes default pgx.QueryExecModeExec is the tested one; WithExecMode allows CacheStatement, CacheDescribe, DescribeExec, which create or cache statements and are not tested through PgBouncer here; simple protocol is rejected
    Session state the test image cannot track search_path set at startup; set it per transaction. vecsearch.Settings and Tx.SetLocal are transaction-local and safe
    Migrations do not run momo migrate through a transaction pooler: the lock is a session advisory lock; use a direct connection
    Other poolers untested (pgcat, Odyssey, RDS Proxy, Supavisor)

    Feature version floors¶

    Feature Floor Source
    Iterative vector scan settings pgvector 0.8.0 vecsearch/vecsearch.go (vecsearch.Apply)
    MERGE (momo.Merge) PostgreSQL 15; .Returning needs PostgreSQL 17 write_merge.go
    Window functions (LoadPerParentLimit) none enforced; tested on PostgreSQL 16 and 17 rel_load.go, CI
    RETURNING, ON CONFLICT, row locking, savepoints none enforced; tested on PostgreSQL 16 and 17 dialect/dialect.go, CI
    Generated identity columns, OVERRIDING SYSTEM VALUE none enforced; tested on PostgreSQL 16 and 17 CI
    momo.yaml, migration files, momo.sum, snapshots format versions 1 (schema.FormatVersion, migrate.SnapshotFormat, migrate.SumFormat); a newer snapshot format is refused with schema.ErrNewerFormat migrate/

    Stability policy¶

    Item Statement
    Pre-1.0 the README states: "v0.10.0, pre-v1, with no compatibility promise between releases"
    Versioning release-please with bump-minor-pre-major: true and Conventional Commits; breaking changes are marked feat!: or a BREAKING CHANGE: footer (CONTRIBUTING)
    Deprecation process none documented
    Security fixes latest minor only (SECURITY.md)
    Pin your dependency use an exact version in go.mod and read CHANGELOG.md before each upgrade
    Generated code regenerate with momo generate after every upgrade; generated files carry only a format number in their header, so an upgrade rewrites them only when the generated code changes; momo generate --check reports stale ones
