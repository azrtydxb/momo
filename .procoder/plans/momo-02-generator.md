# momo-02-generator — implementation plan

Status: draft
Spec: .procoder/specs/momo.md

## Goal

Deliver `momo generate`: read models and their static `MomoConfig` companions from Go source with `go/packages`, emit deterministic, gofmt-clean, collision-safe typed code through one `Writer`, and expose the CLI, `momo.yaml`, naming presets and the plugin interface, delivering S-2, S-3, S-43 (generated `ColumnByName`), S-62, S-67, S-69, S-70 and S-71.

## Architecture

The generator is a pipeline in package `gen`: `Load` turns package patterns into a `Graph` of `Model`s, each with `Field`s, `Relation`s and a normalized `schema.Table`, using `go/packages` for types and an AST-only reader for `MomoConfig`. `Emit` renders the model package metadata file, one per-model subpackage with typed column and relation descriptors, and `ColumnByName`, through the `Writer`, which is the only file writer and refuses handwritten targets. `cmd/momo` and `gen/config` (momo.yaml) call the same `gen` API, and plugins (plan momo-10) receive the same `Graph` and `Writer`.

## Plan dependencies

This plan assumes `momo-01-foundation` exists and provides, by the names in `docs/ARCHITECTURE.md`: `dialect` (`Name`, `For`), `schema` (`Schema`, `Table`, `Column`, `Index`, `IndexPart`, `ForeignKey`, `Check`, `Enum`, `Load`, `Sort`, `Equal`, `FormatVersion`), the root runtime types `Model`, `Column[T]`, `NullColumn[T]`, `VectorColumn[V]`, `NewColumn`, `NewNullColumn`, `NewVectorColumn`, the `Flag*` constants, `Meta[T]`, `ColumnMeta`, `Modeler[T]`, `Assignment`, `ColumnRef`, `Error`, `ErrValidation`, and the `vector` and `types` packages.

Contract additions this plan needs (requested in the report; `docs/ARCHITECTURE.md` is not edited here): `momo.Config` and `momo.IndexOpts` (companion DSL, Task 1), `momo.Relation[P, C]` with `RelationKind`, `momo.InsertAssignment`, `momo.ReadOnlyColumn[T]`, `momo.NullReadOnlyColumn[T]`, `momo.CreateOnlyColumn[T]`, `momo.ImmutableColumn[T]` and their constructors (Task 12), `momo.ColumnRef` as an interface with `Orderable`, and the `Meta[T]` fields `Schema string` and `TableSchema *schema.Table` as the contract already names them.

## Constraints

- Go: minimum 1.26 in go.mod; CI tests 1.26 and 1.27. Dependencies pinned in go.mod/go.sum.
- Generated execution path performs no struct-tag inspection, no reflection over models and no name-based field resolution per query.
- Generator and migration tooling dependencies (golang.org/x/tools etc.) stay out of the application runtime import graph; benchmark comparison ORMs live in a separate Go module.
- No hidden background goroutines, no implicit migrations at connect time, no unexplained global mutable state.
- Milestone M1 (ARCHITECTURE delivery order). Generator tests that need a database use `testopen.Postgres(t)` or `testopen.Each`, never SQLite; golden and compile tests stay database-free.
- Dependency rule 1 (ARCHITECTURE): `momo`, `dialect`, `schema`, `vector`, `types` import only the standard library and each other. No driver, no x/tools, no YAML.
- Dependency rule 3 (ARCHITECTURE): `gen`, `importer/*`, `migrate/*`, `cmd/*` may import x/tools, YAML and drivers. Application binaries that import only `momo` + one driver never link them.
- Dependency rule 5 (ARCHITECTURE): Generated model-level code imports only `momo`, `vector`, `types`, `schema` and the model package.
- Generated-file header (ARCHITECTURE): `// Code generated by momo vX.Y.Z (format 1). DO NOT EDIT.` The version is the `gen.Version` constant (`v0.1.0-dev` until release tooling sets it), so output never depends on how the binary was installed.
- Persisted formats carry explicit format versions independent of the module version: schema snapshot JSON (`format_version`), the checksum file header, the `momo_migrations` history table (metadata row), and generated-file headers (generator version).
- Security: identifiers always quoted, values always bound; raw SQL is an explicit escape hatch with a documented contract; parameter values not logged unless explicitly enabled.
- CI: GitHub Actions on free GitHub-hosted runners only (public repo): ubuntu-latest for most jobs, windows-latest for the SQLite/generator suite.
- S-2 (spec, verbatim): "Model declaration with ordinary Go structs plus struct tags for simple options and a statically inspected, typed companion declaration for complex configuration; unsupported companion expressions produce diagnostics with source positions."
- S-3 (spec, verbatim): "`momo generate` code generator (go/packages + type info): typed column descriptors and predicates, mutation helpers, relation metadata, argument binding, scanners, schema metadata; deterministic, gofmt-clean, no live database, cross-package, collision-safe, marks generated files, never overwrites handwritten files, `--check` for staleness, `go generate` integration."
- Companion reading (spec, verbatim): "Only literal arguments and field references of the form `&d.Field` are accepted; anything else is a diagnostic."
- Failure mode (spec, verbatim): "**Generator input invalid**: diagnostics with file:line:col; no partial output written."
- Edge case (spec, verbatim): "Identifiers that are reserved words, contain quotes, or two Go names normalizing to the same identifier/package name."
- Edge case (spec, verbatim): "Models in a package other than main; import aliases; build-tag-constrained files; custom named types and codecs."
- Spec ambiguity: the spec's Model declaration section says every generated file starts with `// Code generated by momo. DO NOT EDIT.`; this plan uses the ARCHITECTURE header above because the contract is binding. The report lists this for resolution.
- Testing rule: no test touches a live database. Golden files are updated only with `go test -run <Name> -update` and reviewed in the diff.
- Test helper convention: the golden helper is `internal/golden` (Task 1).
- Plan checker: each `Files:` line below lists every file the task creates or modifies, and nothing else.

- Cross-plan prerequisites inside M1 (sprint 2 dependency map, 2026-11-05): plan momo-02 needs momo-04 Task 1 (schema managed-object types: Task 1's companion methods and Task 27), momo-06 Task 2 (`Relation` descriptor: Tasks 13 and 28) and momo-09 Task 1. Interfaces:

- Produces (package `tags`): `type Problem struct{ Msg string }`; `type Tags struct` with fields `Skip bool` (raw value `-`), `Column, Type, Collate, Default, Check, Comment, Enum, Table, Schema, Prefix, Fk, Join, OnDelete, OnUpdate, SoftDelete, TimeUnit, IndexName, UniqueName, Sort, Nulls, Method, View string`, `Materialized bool`, `Rel, PolyType, PolyValue string`, `Size, Precision, Scale, Dim int` and booleans `PK, NotNull, Nullable, Identity, Version, CreatedAt, UpdatedAt, ReadOnly, CreateOnly, Immutable, Sensitive, Embedded, NoConstraint, BelongsTo, HasOne, HasMany, ManyToMany, Index, Unique`.
- Produces: `func Parse(raw string) (Tags, []Problem)`.
- Grammar: the raw value is a comma-separated list of `key` or `key:value`. The value is everything after the first `:` up to the next comma, so a value cannot contain a comma. A stray piece after a comma is reported as an unknown tag option; values that need commas go in the companion (Tasks 9 and 10). Keys are case-sensitive lowercase.
- Vocabulary. Any other key yields `unknown tag option "<key>"`.
  - Bare keys: `pk`, `identity`, `version`, `notnull`, `nullable`, `read_only`, `create_only`, `immutable`, `sensitive`, `embedded`, `no_constraint`, `belongs_to`, `has_one`, `has_many`, `many2many`, `materialized`, `created_at[:unix|unixmilli|unixnano]`, `updated_at[:unix|unixmilli|unixnano]`.
  - Valued keys: `column:<name>`, `type:<sql type>`, `collate:<name>`, `default:<sql expr>`, `check:<sql expr>`, `comment:<text>`, `enum:<name>`, `table:<name>`, `schema:<name>`, `view:<name>`, `rel:<kind>` (belongs_to, has_one, has_many or many2many; the same kinds as the bare keys), `polytype:<column>` and `polyvalue:<value>` (polymorphic relations, Task 13), `prefix:<text>`, `fk:<GoFieldName>`, `join:<table>`, `on_delete:<action>`, `on_update:<action>`, `soft_delete:timestamp|unix|bool`, `method:<name>`.
  - Integer keys: `size:<int>`, `precision:<int>`, `scale:<int>`, `dim:<int>`. `dim` is the dimension for `vector.Vector`, `vector.HalfVector`, `vector.SparseVector` and `vector.Bits` fields. The Go type selects the SQL type (Task 11), so there is no `vector:`, `halfvec:`, `sparsevec:` or `bit:` key.
  - Index keys: `index[:<name>]`, `unique[:<name>]`, `sort:asc|desc`, `nulls:first|last`.
- Integer values must parse with `strconv.Atoi`; otherwise the message is `<key> must be an integer`. A valued key with no value gives `<key> requires a value`.

Interfaces:

- Produces (package `naming`): `type Namer interface { TableName(goModel string) string; ColumnName(goField string) string; JoinTableName(owner, target string) string }`.
- Produces: `type Momo struct{}` implementing `Namer`; `func ToSnake(s string) string`; `func Plural(s string) string`; `func ByName(name string) (Namer, error)` returning the presets `"momo"` (this task), `"gorm"`, `"bun"`, `"ent"` (Task 5). Unknown names return `fmt.Errorf("unknown naming preset %q", name)`.
- Rules for `Momo`: `TableName` = `Plural(ToSnake(goModel))`; `ColumnName` = `ToSnake(goField)`; `JoinTableName(owner, target)` = `TableName(owner) + "_" + TableName(target)`.
- `ToSnake`: insert `_` before an uppercase letter when the previous rune is a lowercase letter or digit, or when the previous rune is uppercase and the next rune is lowercase; then lowercase everything. Examples: `UserID`→`user_id`, `HTTPStatus`→`http_status`, `CreatedAt`→`created_at`.
- `Plural`: irregular map `person→people`, `child→children`, `man→men`, `woman→women`, `mouse→mice`; else if the word ends in consonant+`y` replace `y` with `ies`; else if it ends in `s`, `x`, `z`, `ch` or `sh` append `es`; else append `s`. Apply to the last `_`-separated word only.

```go
package genstats

import (
	"encoding/json"
	"os"
	"path/filepath"
	"reflect"
	"strings"
	"testing"
)

func TestGenStatsOutput(t *testing.T) {
	r, err := Report([]string{"../../testmodels/example/..."}, true)
	if err != nil {
		t.Fatal(err)
	}
	if len(r.Files) == 0 {
		t.Fatal("no files measured")
	}
	var genBytes, handBytes, total int64
	sawHandwritten := false
	for _, f := range r.Files {
		if !filepath.IsAbs(f.Path) {
			t.Fatalf("path %q is not absolute", f.Path)
		}
		fi, err := os.Stat(f.Path)
		if err != nil {
			t.Fatal(err)
		}
		if fi.Size() != f.Bytes {
			t.Fatalf("%s: recorded %d bytes, on disk %d", f.Path, f.Bytes, fi.Size())
		}
		if f.Generated != (filepath.Base(f.Path) == "momo_gen.go") {
			t.Fatalf("%s: generated flag is %v", f.Path, f.Generated)
		}
		if f.Generated {
			genBytes += f.Bytes
		} else {
			handBytes += f.Bytes
			if strings.HasSuffix(f.Path, "models.go") {
				sawHandwritten = true
			}
		}
		total += f.Bytes
	}
	if !sawHandwritten {
		t.Fatal("the handwritten example models are not measured")
	}
	if genBytes == 0 {
		t.Fatal("no generated bytes measured")
	}
	if genBytes != r.GeneratedBytes || handBytes != r.HandwrittenBytes || total != r.TotalBytes {
		t.Fatalf("totals: generated %d/%d, handwritten %d/%d, total %d/%d",
			genBytes, r.GeneratedBytes, handBytes, r.HandwrittenBytes, total, r.TotalBytes)
	}
	b, err := json.Marshal(r)
	if err != nil {
		t.Fatal(err)
	}
	var back Report
	if err := json.Unmarshal(b, &back); err != nil {
		t.Fatal(err)
	}
	if !reflect.DeepEqual(back, r) {
		t.Fatal("JSON round trip is not lossless")
	}
}
```

func literalOf(t *testing.T, src []byte, name string) string {
	t.Helper()
	s := string(src)
	start := strings.Index(s, "var "+name+" = momo.Relation[")
	if start < 0 {
