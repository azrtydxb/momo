## Retro

What slowed us down:

- **Generated content went through a CI round trip every time.** Each change to a generator template needed a regen workflow run on a throwaway branch, a commit of its artifact, and then another full run for `docs/reference.md`. Several branches spent more time waiting for artifacts than writing code.
- **Fresh reviews found real bugs on branches that were already green.** Examples: the GraphQL error presenter leaked database text; `Not(And(...))` and `JoinSQL("OR", ...)` bypassed the Using/From guard; view models broke every plugin generator's table lookup. Each one cost a fix round and another CI cycle, but none of them reached `main`.
- **Agent edit scripts failed silently.** One script never wrote the OpenAPI input schema, and another cut two story files down to a single line. Both passed the agent's own checks, and the integrator found them only at merge time.
- **A test called fixed was still flaky.** `TestFilteredANNIterativeScan` was "fixed" twice before the real cause was found: every row had the same vector, because PostgreSQL evaluated an uncorrelated `random()` subquery once.

What we change next sprint:

- **Before a story branch merges, the integrator diffs each file's line count against the merge base**, and treats any file that shrinks sharply as damaged until checked.
- **Generator-template stories start from a regen artifact taken at the beginning**, so the expected generated output is known before the review round.
- **A flaky-test fix names its root cause**, with the evidence, before it is called fixed. Two green runs is not a root cause.

One adaptation worth keeping:

- **v0.5.0 shipped the port issues on their own** (the user's "ship issues first"), while backlog work kept merging into the same sprint for 0.6.0. Orbit got its release the same day, and the review-heavy ecosystem branch never delayed it.
