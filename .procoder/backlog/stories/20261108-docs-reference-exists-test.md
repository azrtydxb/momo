# Docs reference test: backticked identifiers resolve, every exported name is documented

Status: open
Created: 2026-11-08
Epic: momo-14-structure-and-docs
Sprint: 006-sprint-6-split-the-root-package-into-subpackages-and-keep

## Description

Docs name identifiers in backticks (`ReadOnlyColumn`, `momo.Hook`, `Relation.Has`) and nothing checks that they exist; the stale 'planned' names in `docs/ARCHITECTURE.md` are the symptom. Add `TestDocsIdentifiersResolve` in `internal/docscheck` (the package momo-13 creates; if story 255 has not landed, create it with only this file and let momo-13 reuse it) that extracts every backticked token shaped like a Go identifier or `pkg.Name` or `Type.Method` from `README.md`, `docs/*.md` and `llms.txt`, and resolves it with `go/types` over the module's packages (load with `golang.org/x/tools/go/packages`, already a dependency for the generator). Unresolvable tokens fail unless they are in an allow file with a reason (SQL keywords, other libraries' names). The second test, `TestExportedIdentifiersDocumented`, loads the exported identifiers of `momo` and the feature subpackages and requires each to appear either in `docs/ai-guide.md` or in the generated reference `docs/reference.md` (a table of package, identifier, one-line doc-comment synopsis, produced by `internal/gendocs`). An identifier with an empty doc comment fails regardless. The baseline of existing undocumented identifiers is a ratchet file that may only shrink. Compiling the Go code blocks is momo-13 story 255 and is not repeated here.

## Acceptance criteria

- [ ] an invented name `momo.NoSuchThing` in backticks in a doc fails `TestDocsIdentifiersResolve` with file and line (red evidence on CI)
- [ ] `Relation.Has`, `momo.Hook` and `types.JSON` resolve; method references are resolved on the receiver type, and generic types are matched without type parameters
- [ ] an exported identifier with no doc comment fails `TestExportedIdentifiersDocumented`; the current exceptions are listed in `internal/docscheck/testdata/undocumented.txt`, which the test refuses to grow
- [ ] `docs/reference.md` is generated by `go generate`, lists every exported identifier of the core and feature packages with its synopsis, and is covered by the CI drift check of story generated-capability-matrix-and-type-table
- [ ] the stale 'Planned, not implemented' names in `docs/ARCHITECTURE.md` either resolve or the section is removed (done in story stale-docs-sweep; this test is the guard that keeps it so)
- [ ] the test runs without a database and finishes inside the unit job's time budget
