## Description

Append-only tables need ids that a client can never supply. `identity` always renders `GENERATED BY DEFAULT AS IDENTITY`. `--from-db` models an ALWAYS column as by default, so the baseline differs on every adopted database that uses one. The ask is in GitHub issue #56, from the Kuvryn Owl Enterprise port.

## Acceptance criteria

- [x] a tag option `identity:always` renders `GENERATED ALWAYS AS IDENTITY`; plain `identity` is unchanged (unit test pins both)
- [x] the PostgreSQL inspector reports the kind, `--from-db` emits `identity:always`, and baseline on such a database reports no mismatch (integration test)
- [x] inserts omit the column and read it back with RETURNING (integration test)
- [x] diff switches between the two kinds with ALTER COLUMN ... SET GENERATED (metadata-only), proven by an integration test (TestDeclaredIdentityAlways)
- [x] docs describe it; issue #56 is referenced in the commit
