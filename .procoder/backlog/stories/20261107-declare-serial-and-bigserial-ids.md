# Declare serial and bigserial ids

Status: done 2026-11-07
Created: 2026-11-07
Epic: momo-02-generator
Sprint: 004-sprint-4-adoption-gaps-from-kuvryn-license-composite-pk

## Description

Existing databases often use BIGSERIAL ids (issue #14). momo only emits GENERATED BY DEFAULT AS IDENTITY for pk,identity, so Baseline needs a hand-edited init migration and every later diff proposes converting the columns. Done means a tag declares a serial or bigserial id, the DDL emits it, the introspector recognises an existing serial column (sequence owned by the column with a nextval default), and diff treats it as matching.

## Acceptance criteria

- [x] A struct tag (e.g. pk,serial) emits serial for 32-bit and bigserial for 64-bit integer ids in CREATE TABLE (golden test)
- [x] Introspecting a table with a bigserial id yields the same schema as the model, so diff is empty (integration test on CI)
- [x] Inserts on a serial id return the generated key via RETURNING like identity ids (integration test on CI)
- [x] Non-PostgreSQL dialects refuse or map the tag explicitly (test)
- [x] docs describe the tag

## Evidence

- Golden DDL: TestRenderSerialCreateTable and TestRenderSerialAddColumn (migrate/postgres) assert bigserial, serial and smallserial; TestSerialTagBuildsSerialColumns (gen) maps int64 and int32 ids; CI run 42343182065 success.
- Introspection: TestSerialIntrospectionMatchesModel and TestSerialRenderedDDLRoundTrips (migrate/postgres, integration) assert schema.Equal and an empty migrate.Diff for a hand-made BIGSERIAL table; CI run 42343182065 success.
- Insert: TestSerialInsertReturnsGeneratedKey (migrate/postgres, integration) inserts without the key and reads id and seq back through RETURNING; CI run 42343182065 success.
- Other dialects: TestSerialTagRefusals/sqlite and /mysql (gen) assert the diagnostic that serial is not supported; CI run 42343182065 success.
