# Declare serial and bigserial ids

Status: open
Created: 2026-11-07
Epic: momo-02-generator
Sprint: 004-sprint-4-adoption-gaps-from-kuvryn-license-composite-pk

## Description

Existing databases often use BIGSERIAL ids (issue #14). momo only emits GENERATED BY DEFAULT AS IDENTITY for pk,identity, so Baseline needs a hand-edited init migration and every later diff proposes converting the columns. Done means a tag declares a serial or bigserial id, the DDL emits it, the introspector recognises an existing serial column (sequence owned by the column with a nextval default), and diff treats it as matching.

## Acceptance criteria

- [ ] A struct tag (e.g. pk,serial) emits serial for 32-bit and bigserial for 64-bit integer ids in CREATE TABLE (golden test)
- [ ] Introspecting a table with a bigserial id yields the same schema as the model, so diff is empty (integration test on CI)
- [ ] Inserts on a serial id return the generated key via RETURNING like identity ids (integration test on CI)
- [ ] Non-PostgreSQL dialects refuse or map the tag explicitly (test)
- [ ] docs describe the tag
