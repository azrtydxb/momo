## Deviations from the plan

- Default(literal) is a database default, not a Go default as the plan text says: Ent writes it into the column (checked in the DDL above) and also applies it in Go when the setter was not called. The importer keeps it as `default:` and reports zero-value-handling (Momo writes the zero value of a non-pointer field), not go-default. DefaultFunc, Default(time.Now), UpdateDefault and the time mixins are go-default, as the plan says. `TestImportEnt` asserts implicit-save and go-default are both reported, as the plan does.
- implicit-save is reported for every edge (Ent writes an edge only when its setter is called), not only for edge.From with Ref.
- The fixture compares against PostgreSQL (Ent's migration on the CI service container), not SQLite with modernc: only the PostgreSQL migration dialect exists. The fixture module requires entgo.io/ent v0.14.6 and pgx.
- Momo shapes foreign keys differently on purpose (<table>_<column>_fkey), which `schemafixture.AsMomoWould` normalises on Ent's side and the importer reports as naming. Composite indexes are reported as dropped-index and not imported, as in the GORM importer.
- importer.Field gained Identity (an identity bigint key, which is what Ent creates), emitted as the `identity` tag; the new report kind go-side-rule covers what Ent runs in Go only (validators, Immutable, enum value lists, hooks, policies and interceptors). importer/emit.go now writes numeric(p,s) as `precision:p,scale:s` tags because a `type:` value cannot carry a comma (this also fixes the GORM reader's numeric(p,s) output).
- The generated Ent client is committed under internal/compat/entfixture/ent. It was produced by a temporary GitHub Actions job (go mod tidy, `go run -mod=mod entgo.io/ent/cmd/ent generate ./ent/schema`, go mod tidy), together with go.mod and go.sum; regenerate with `go generate ./ent` in the fixture module. internal/repocheck now accepts the standard Go `// Code generated ... DO NOT EDIT.` marker as an alternative to the SPDX header, and gosec (Makefile and the gosec workflow) skips internal/compat/entfixture/ent.
- Read the schema package statically; not executed (decision D-11.1). Reported rather than guessed: a Fields, Edges, Indexes or Mixin method that is not a single returned slice literal, field.JSON, UUID, Other and the slice types, GoType, custom id fields, many-to-many edges and edge.Through, a Default that is not a literal or time.Now, entsql annotation keys other than Table, Default, DefaultExpr and OnDelete, OnDelete on an edge.From (Ent reads it from the edge.To), Nillable without Optional, Unique on an edge field, index annotations, and every unknown builder method. Annotations that call or build a type of another imported package (entgql and the like) do not change the SQL schema and are ignored; an annotation that cannot be shown to come from another package (a variable, a helper call) is reported as unsupported; Comment, Sensitive, StructTag and Deprecated likewise.
- Limits: SchemaType is read only for the postgres key (other dialects are reported as naming); the Ent Config and Annotations table names are read only from string literals; local mixin types are resolved only inside the read directory.
