# Root package split: inventory, target layout, ordering

Date: 2026-11-08. Branch base: sprint-5 (merged). Method: file reading, grep and a throwaway dependency script over the non-test root files. No `go build`, `go test`, `go vet` or docker was run. Line counts and identifier lists come from reading the source, not from the type checker, so each story re-verifies its file list with a compile on CI.

Decision being planned: "Root-package structure and always-current docs" (decisions.md, 2026-11-08): a breaking split after sprint-5 lands on main, mechanics into `internal/`, a file-prefix taxonomy, an architecture test, and docs-freshness guards.

## 1. What the root package is today

57 non-test files, about 13,960 lines, one exported surface of roughly 600 identifiers. The generator pins a much smaller contract: generated code references only `Meta`, `ColumnMeta`, `TableRef`, `Model`, `Projection`, `Config`, `Relation`, `Through`, `Discriminator`, `NewColumn`, `NewNullColumn`, the read-only, create-only and immutable vector column constructors, `NewVectorColumn`, `Select`, `New`, `ErrValidation`, `ColumnRef`, `FlagNullable` and the `SoftDelete*` constants. So the generated-code contract is the core and cannot move.

Two Go rules decide everything that follows:

1. Methods live in the package of their receiver type. A method cannot be moved without moving, or wrapping, its type.
2. A package outside `momo` can implement `momo.Expr` (one exported method, `AppendSQL`) but cannot implement `momo.Expression[T]` or `momo.Predicate`, because `Expression[T]` has the unexported method `resultType`. It also cannot call `Builder.argFor`, `Builder.renderSens`, `Builder.unsupported`, `Builder.writeByte` or `flagsOf`, and it cannot build an `Assignment` or an `Order` with unexported state. Moving an expression feature therefore needs a small, deliberate exported "expression-extension API" in the core first (section 6, step 2).

A consequence of rule 2 that makes the plan feasible: a type in a subpackage that embeds an exported core struct inherits that struct's unexported methods, and satisfies `Expression[T]`. So the extension API can be a single exported struct (the current `exprOps[T]`, renamed `Ops[T]`) plus a few exported helpers, instead of exporting `resultType`.

A consequence that limits the plan: no deprecated type aliases are possible. A subpackage imports `momo`, so `momo` cannot alias `fts.TSExpr`. Every move is a hard source break, which the decision already accepts (pre-v1, bump-minor-pre-major is on in release-please-config.json, so the release is 0.4.0).

## 3. Proposed target layout

```
momo                     core: DB, Tx, Querier, driver interfaces, errors, Builder, Compiled,
                         Expr/Expression/Predicate, Column family, Assignment/Order, Meta/Model,
                         Select/Insert/Update/Delete/Upsert, Relation and loading, hooks,
                         Func escape hatch, vector columns, raw SQL
momo/fts                 full-text search expressions
momo/arrayop             PostgreSQL array predicates
momo/jsonop              JSON text, path, containment, has-key
momo/agg                 ordered, filtered, within-group aggregates and JSON object builders
momo/timeop              Extract, DateTrunc, Interval arithmetic, AtTimeZone, Now
momo/sqlfn               Substr, Lower, Upper, Length, Case, Cast, Concat, arithmetic, CurrentSchema
momo/advisory            advisory lock helpers over Querier
momo/vecsearch           pgvector search settings (hnsw, ivfflat) applied to a Tx
momo/vecop               vector distance builders (optional, needs VectorSource accessor)
momo/obs                 ready-made Hook implementations (new, non-breaking)
momo/internal/sqlscan    raw SQL tokenizer and placeholder parsing
momo/internal/redact     sensitive-argument masking
momo/internal/keyenc     key tuple encoding
momo/internal/chunk      bind-limit chunk arithmetic
```

Existing subpackages stay as they are: `dialect`, `schema`, `types`, `vector`, `migrate`, `driver/pgxdriver`, `gen/*`, `cmd/momo`. There is no `importer` package in the tree (ARCHITECTURE.md lists `importer/{gorm,bun,ent}` as planned, and `internal/namingrec` holds only recorder fixtures), so there is nothing to keep separate yet.

Corrections to the brief, from reading the code:

- There is no tenant filter and no N+1 detector in the root. The root has the hook interfaces (`Hook`, `QueryEvent`, `RelationHook`, `RelationEvent`, `RecordPoolWait`, `WithHook`, `WithArgLogging`) and row-level-security plumbing (`WithTxSetup`, `WithImplicitTx`, `SetConfigLocal`, `Tx.SetLocal`). `DB` holds the hook lists and calls them, so the interfaces cannot leave `momo`. `momo/obs` is therefore a new package of implementations (the recorder now in `internal/obstest`, an N+1 detector built on `RelationHook`, a `log/slog` hook), added without breaking anything. Tenant isolation stays row-level security through `WithTxSetup`; a tenant helper in `obs` or elsewhere is out of scope.
- Window functions are not a root feature; `dialect.Dialect.WindowFunctions` is a capability flag only. No analytics package is proposed.
- "Shape normaliser": nothing in the root normalises shapes. The nearest are `schema/normalize*.go` (already its own package) and `relationShape` in `gen/relations.go`. Neither is a root concern, so no internal package is proposed for it.

## 5. File-prefix taxonomy for what stays in root

Go has no folders for one package, so file names carry the structure. Rule: every non-test root file is `doc.go` or starts with one of the prefixes below, either bare (`db.go`) or `<prefix>_<topic>.go`. Test files take the subject file's name plus `_test`, `_internal_test` or `_integration_test`. A repocheck test fails on any other name. It starts as a ratchet (a list of today's exceptions that may only shrink) and the rename story empties the list.

## 9. Findings for the parent

- The split is smaller than the brief suggested: about 2,400 lines of leaf expression libraries and helpers leave the root (fts, arrayop, jsonop, agg, timeop, sqlfn, search settings, advisory, vector distances), plus about 450 lines of mechanics to `internal/`. The query builders, relations, column family and DB/Tx stay, because their methods bind them to generic receiver types.
- The enabling change is a core "expression-extension API". Without it, nothing expression-shaped can move, because `Expression[T]` cannot be implemented outside the package. That step is additive and ships first.
- Every move is a hard break with no alias bridge (import cycle). One 0.4.0 release with `docs/upgrading.md` and the `moves/` check keeps the break honest.
- The brief's tenant filter, N+1 hook and window functions do not exist as root features; `momo/obs` is new work, scoped as non-breaking.
