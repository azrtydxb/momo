    Go to SQL type mapping¶

    This page lists which SQL column type Momo uses for each Go field type, what survives a round trip, and where the edges are. The tables are checked by tests: TestTypeMappingDoc fails when a row here disagrees with the generator's type map or a codec's SQLType, and TestTypeMapping creates a column of each documented PostgreSQL type on a live server, and the generated SQLite type on a live SQLite database, and round-trips edge values through it.

    How a type is chosen¶

    1. A field whose type implements the codec contract (types.Codec: Scan, Value and SQLType) uses its own SQLType. This is how types.TimeOfDay and types.Hstore get their columns.
    2. Otherwise the generator maps the Go type with its built-in table (package gen/typemap). A pointer and the sql.Null* wrappers map like the type they wrap: nullability is a column property, not a type property.
    3. A Go type with no mapping (for example uint64 or map) makes typemap.Map return an error wrapping momo.ErrUnsupported, which the generator reports at the field. Give the type a codec or declare the column yourself.

    Generated mappings¶

    N is the size tag for string and the dim tag for vector types. A vector.Vector or vector.HalfVector field without dim is supported: it maps to the bare vector or halfvec type, a dimensionless column that holds embeddings of any size (see vectors.md). vector.SparseVector and vector.Bits require dim. SQLite has no vector types. A slice of a scalar maps to the PostgreSQL array of its element type; SQLite has no array columns, so the generator rejects them there.

    The MySQL column is what typemap.Map returns for MySQL: the generator emits no MySQL models, so every Go type shows unsupported there until it does. Only an error that wraps momo.ErrUnsupported shows as unsupported; any other error from typemap.Map fails the generation of this table.

    The PostgreSQL type of time.Time can be changed for the whole project with the types: section of momo.yaml, for example types: {time.Time: timestamp(3)} for a database created by Prisma (see naming: prisma in ai-guide.md). Only time.Time can be overridden; a type: tag on a field still wins, and SQLite ignores the setting. timestamp(3) stores a wall clock without a zone, so follow the timestamp notes below and pass UTC times.

    On SQLite, bool is stored as 0 or 1, and time.Time, types.UUID, types.Date, types.Numeric and types.JSON[T] are stored as text. The SQLite column is what the generator emits. The SQLite driver (driver/sqlitedriver, cgo, not on Windows) reads text columns back into time.Time, *time.Time, sql.NullTime, sql.Null[time.Time] and types.Date, whatever the column was declared as.

    Codec-provided mappings¶

    These types are not in the generator's table. Their own SQLType method names the column; the generator's table is the fallback for everything else.

    Go type PostgreSQL SQLite
    types.TimeOfDay time TEXT
    types.Hstore hstore TEXT
    types.TSVector tsvector TEXT
    types.TSQuery tsquery TEXT

    types.Hstore needs the hstore extension; the vector types need vector (pgvector). Momo never runs CREATE EXTENSION for you.

    Mappings you declare yourself¶

    The generator never emits these columns, but the Go types work against them when you write the DDL (or a migration) by hand. There is no SQLite column to document because nothing generates one.

    Go type PostgreSQL SQLite
    time.Time (timestamp) timestamp n/a
    string (decimal) numeric n/a

    Edge values and behavior¶

    Each statement below is asserted by a test against PostgreSQL. The generated SQLite column of every row is also round-tripped on a live SQLite database, except NaN, which SQLite does not have (see Floats).

    • Integers: math.MaxInt64 and math.MinInt64 round-trip through bigint; int is 64-bit and maps to bigint. A value that does not fit the column (an int64 above math.MaxInt16 into smallint) is a database error, not a silent truncation. uint64 has no mapping and is rejected when bound if it exceeds math.MaxInt64.
    • Floats: NaN, +Inf and -Inf are legal double precision and real values and round-trip. Compare with math.IsNaN, since NaN != NaN. SQLite has no NaN: binding a float32 or float64 NaN (or a pointer to one) is ErrValidation and nothing is stored, rather than a silent NULL. +Inf and -Inf are legal REAL values.
    • Strings: any valid UTF-8 round-trips, including quotes and backslashes (they are bound, never interpolated). PostgreSQL rejects U+0000 in text. A string longer than size is a database error on character varying(N).
    • []byte: nil stores NULL; an empty non-nil slice stores an empty bytea.
    • time.Time on timestamptz: the instant is preserved, the zone is not. A value written at +05:30 reads back as the same instant in the server session's location, so compare with Time.Equal, not ==. Precision is microseconds; finer digits are cut. Times before 1970 and year 9999 work.
    • time.Time on timestamp (no zone): you store a wall clock. Pass t.UTC() and treat the column as UTC; a value in another zone is stored as its UTC wall clock.
    • types.Date: stores the year, month and day of Time in its own location; it reads back at midnight UTC. Compare the date, not the zone. PostgreSQL infinity and -infinity round-trip through the Infinity and NegInfinity fields (Time is ignored while one is set, and zero after a read); IsFinite tells an ordinary date from a special one. SQLite and MySQL have no special dates: a types.Date with a flag set is ErrValidation and nothing is stored, also inside a sql.Null. Setting both flags is an error.
    • types.Numeric: an exact decimal kept as text in Decimal ("-12.50"; empty is 0). PostgreSQL numeric returns what it stored, so a value beyond float64 precision and its scale survive. NaN, Infinity and NegInfinity round-trip through their flags (set at most one, and leave Decimal empty); IsFinite, IsNaN, IsInfinite and Sign classify a value (Sign is 0 for NaN). Infinity and -Infinity need PostgreSQL 14 or later (NaN is older); CI covers PostgreSQL 16 and 17. types.ParseNumeric reads PostgreSQL text and rejects an exponent or anything that is not a number. Scanning also takes an int64 and a float64 (what SQLite returns for an expression); it does not take a pgtype.Numeric.
    • SQLite and MySQL have no NaN or infinity: binding one in a types.Numeric (also inside a sql.Null) is ErrValidation, as for a float NaN on SQLite. The column is TEXT there, so the database does not order or add it as a number, and a precision or scale tag still generates TEXT, not numeric(p,s): SQLite would give that NUMERIC affinity and turn 12.50 into 12.5. On PostgreSQL the tags generate numeric(p,s). On PostgreSQL the sqlfn arithmetic helpers (sqlfn.Add, sqlfn.Sub, sqlfn.Mul, sqlfn.Div and their Expr forms) and sqlfn.NullIf accept a types.Numeric, and the database does the exact arithmetic; on SQLite and MySQL they fail with ErrUnsupported, because the column is TEXT there and + would go through floating point. types.NumericFromInt64 and types.NumericFromFloat64 build a value from a Go number (a float64 is already binary: 0.1 gives "0.1", its shortest decimal, and NaN or an infinity is an error). Momo does no other arithmetic on a types.Numeric.
    // agent_conversation.cost numeric(12,6), momo.Column[types.Numeric]
cost, err := types.NumericFromFloat64(0.000412)
if err != nil { return err }
agentconversation.Cost.SetExpr(sqlfn.Add(agentconversation.Cost, cost))
// roughly: SET cost = (agent_conversation.cost + $1), exact in numeric
    • types.UUID: round-trips all 16 bytes, including the all-zero UUID.
    • types.JSON[T]: encodes with encoding/json. An empty slice and a nil slice are different JSON ([] and null) and read back as such. Query it with jsonop.Text, jsonop.Path, jsonop.Root (a scalar at the root), jsonop.Contains and jsonop.HasKey, and compute with jsonop.DeleteKey, jsonop.Concat and jsonop.Set (package github.com/azrtydxb/momo/jsonop; jsonop.Concat and jsonop.Set are PostgreSQL only and need jsonb). A nullable column holds either SQL NULL or the JSON literal null; an extraction is NULL for both and for a missing key, so test the column itself with IsNull.

    Reading keeps the two apart when you scan into a *types.JSON[T] field (a nullable column): SQL NULL gives a nil pointer, and the JSON literal null gives a non-nil pointer whose IsNull method returns true. Writing it back stores the JSON literal null, not SQL NULL; a nil pointer stores SQL NULL. types.JSONNull builds a JSON null value to write. This holds on PostgreSQL (jsonb, native and FromSQLDB drivers), SQLite and MySQL, where the column is TEXT and any stored text that is null (white space around it ignored) counts as the JSON null. A plain, non-pointer types.JSON[T] field still errors on SQL NULL and reads the JSON null as the zero T with IsNull true.

    IsNull stays true after a read while V is the zero value of T or still encodes as null (a json.RawMessage holding null, the generated default type, or a T with its own UnmarshalJSON). To give a value read as null new contents, assign through types.JSON.Set or a fresh types.JSON[T]{V: v}. Assigning V directly to its zero value (false, 0, "") keeps the JSON null, because the zero value cannot be told from an untouched V.

    types.JSON[T] has a private field and no MarshalJSON. Two values compare equal with == only when the null state matches, so a scanned null differs from types.JSON[T]{}; go-cmp needs a comparison option that ignores the null state. encoding/json renders any types.JSON[T] as {"V":...}, and types.JSONNull[T]() as {"V":null}: the null state does not survive an API round trip through encoding/json.

    Grouping by an extraction works only for plain keys (letters, digits, underscore) and not on a sensitive column; see the AI guide pitfalls.

    • types.TimeOfDay: nanoseconds since midnight, truncated to microseconds (PostgreSQL time precision); 86399999999000 is the last representable value, and a value outside one day is an error.
    • types.Hstore: a nil *string value is an hstore NULL; keys and values with quotes and backslashes are escaped.
    • types.TSVector and types.TSQuery: the server's text form, with the lexemes sorted and normalized, so write values in that canonical form to compare them with ==. An empty tsvector reads back empty. Full-text expressions are PostgreSQL only (see docs/fulltext.md).
    • []string on text[]: elements containing commas, quotes, the text NULL, or empty strings round-trip; an empty slice reads back empty.
    • Slices as arrays: only []string, []int16, []int32, []int64, []bool, []float32, []float64 and []types.UUID (uuid[]) map, and so does a []uuid.UUID from github.com/google/uuid (see the next item). []int is not mapped, because its width is platform dependent; use []int64. []string with a size tag becomes character varying(N)[]. A nil slice binds as NULL, so inserting it into a NOT NULL array column fails with a not-null violation; pass an empty non-nil slice (it stores {}), or give the column a default '{}' and omit it. The array predicates bind a nil value list as an empty array, never NULL.
    • uuid.UUID, *uuid.UUID and []uuid.UUID from github.com/google/uuid map to uuid and uuid[] on PostgreSQL and uuid.UUID to TEXT on SQLite (canonical text; []uuid.UUID has no SQLite column), with no type: tag. MySQL has no uuid mapping, as for types.UUID. The generator recognizes the type by its import path and adds no dependency to momo; your module requires github.com/google/uuid only when your models import it. --from-db writes these types with introspect.uuid: google. A named type over uuid.UUID (type ID uuid.UUID) is not mapped: give the field type:uuid. A UUID type of another package is not mapped either.
    • Decimal: carry numeric as types.Numeric (exact, with NaN and the infinities), or as a string to avoid binary floating point. Values beyond float64 precision round-trip exactly, and numeric also accepts NaN.

    Null handling¶

    A column that can be NULL needs a Go type that can hold NULL: a pointer (*int64), a sql.Null* wrapper, or a type whose Scan accepts nil. Scanning NULL into a plain int64 or into a codec from the types package is an error, never a silent zero value.
